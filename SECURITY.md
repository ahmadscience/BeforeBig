# Reporting security issues

Do not put credentials, live exploit details, personal data, magic links, or private moderation evidence in a public issue.

Use **GitHub → Security → Advisories → Report a vulnerability** if private reporting is enabled. If it is unavailable, open an issue asking the maintainer to establish a private reporting channel, without disclosing the vulnerability. No dedicated security email or response-time commitment has been established.

Include affected code/version, impact, reproduction steps using fictional data, and a proposed fix if available. Rotate exposed credentials immediately through the provider that issued them.

This early project has no declared long-term support branches. Security fixes target the current default branch. See [the security model](docs/SECURITY.md) for implemented controls and known operational gaps.
